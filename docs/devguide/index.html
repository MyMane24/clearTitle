    clearTitle Developer Guide

    clearTitle is an end-to-end property title verification platform for Karnataka property documents. This guide documents the system as it is implemented: architecture, data flow, pipeline stages, APIs, storage, deployment, and rollback strategy.

    Purpose

    This documentation is written from the application itself (README, source code, docker-compose, Dockerfile) to serve as a practical developer guide. It explains what exists, how it works, and how to operate it safely.

    Quick Start

    git clone https://github.com/MyMane24/clearTitle.git
cd clearTitle
cp .env.example .env
# fill SARVAM_API_KEY, GROQ_API_KEY, GEMINI_API_KEY
docker compose up --build

    App runs at http://localhost:8000 (dashboard at http://localhost:8000/#/app). phpMyAdmin at http://localhost:8080.

    Architecture Overview

    Layers

    • Frontend: React 19 + Vite + TypeScript, Tailwind CSS 4. Serves landing page (/) and dashboard (/#/app).
    • API: FastAPI (Uvicorn) — auth, cases, results routers.
    • Orchestration: Celery workers with Redis broker/state store.
    • Pipeline: 6 per-document stages (preprocess, OCR, merge, classify, structure, persist) chained per document, joined by chord → finalize → title chain → verify.
    • Storage: MySQL (users, cases, documents, title_chains, verification_results), Redis, filesystem (outputs/, uploads/).

    Document Pipeline

    1. Preprocess (OpenCV) — denoise/deskew/sharpen; non-fatal fallback.
    2. OCR (Sarvam) — per-chunk or full; overlap merge logic.
    3. Merge — dedupe overlaps, rejoin split tables, strip blobs.
    4. Classify — filename-first, then content (English+Kannada). Fails to classification_failed if unknown.
    5. Structure — LLM fills per-type JSON schema (Gemini primary, Groq fallback).
    6. Persist — save to MySQL + write files to outputs/.

    Case-level: Finalize (recompute status, queue analysis if all structured) → Title Chain → Verification (SD vs EC). Verification verdicts are deterministic VERIFIED/NOT_VERIFIED/N/A.

    Storage & Data

    • MySQL tables: users, cases, documents, title_chains, verification_results (DDL via migrations.py, no downgrade path).
    • Filesystem: outputs/ (895 MB+ in practice) is not in git — irreplaceable if lost (requires re-running OCR). uploads/ contains originals.
    • Backups: backups/ holds local mysqldump snapshots (gitignored + .dockerignore'd).

    Deployment & Ops

    Docker

    • Multi-stage: Node 20 builds frontend/dist in stage 1; Python 3.11 runtime copies source + built SPA (COPY --from=frontend-build /ui/dist ./frontend/dist).
    • SPA is baked into the image — changing frontend source requires rebuild; git reset does not change a running image.
    • docker-compose.yml uses build: (no fixed image:), so docker compose build overwrites :latest. Tag images before risky changes.

    Backup & Rollback

    Three layers, separate undo:

    LayerWhatHow to restore
    CodeSourcegit reset --hard <tag> (tag: pre-big-change @ b1196fc)
    Running buildImage (code+SPA)docker tag cleartitle-api:b1196fc cleartitle-api:latest && docker tag cleartitle-worker:b1196fc cleartitle-worker:latest, then docker compose up -d --force-recreate --no-build
    DataMySQL + outputs/Mysqldump (consistent, no locks). outputs/ is filesystem-only — back up separately if needed.

    Database snapshot (safe)

    mkdir -p backups  # PowerShell: New-Item -ItemType Directory backups
docker compose exec -T mysql sh -c 'mysqldump -u root -p"" \
  --single-transaction --skip-lock-tables --no-tablespaces \
  --default-character-set=utf8mb4 --routines --triggers \
  --set-gtid-purged=OFF property_ocr_v2 > /tmp/db.sql'
docker compose cp mysql:/tmp/db.sql "backups/db-.sql"

    Notes: no --databases (prevents implicit CREATE/USE against arbitrary DB), UTF-8 safe, lock-free for InnoDB.

    Verify image matches source

    # Linux/macOS
docker create --name chk cleartitle-api:b1196fc
docker cp chk:/app/backend/services/report.py /tmp/report.py
git hash-object /tmp/report.py
git rev-parse b1196fc:backend/services/report.py  # must match
docker rm chk

    Configuration

    All env vars centralized in backend/config.py. Required keys: SARVAM_API_KEY, GROQ_API_KEY, GEMINI_API_KEY. Optional: BODHAN_API_KEY (probes). MySQL/Redis hostnames are overridden in compose to service names (mysql, redis).

    Prompts & Schemas

    Versioned under backend/prompts/ (.txt files). Load via backend.prompts.loader.load_prompt/load_schema. Extraction schemas live in backend/services/schemas/.

    Notes

    • EC page-split ledger rows are recombined at read boundary (backend/shared/ec_ledger.py) to avoid double-counting.
    • Case verification/title-chain can be re-run independently via results endpoints.
    • PDF report only downloadable once verification has produced results.
    • docs-dev/ contains archived raw Markdown notes (not referenced by this guide). docs/artifacts/ contains HTML exports/reports.
